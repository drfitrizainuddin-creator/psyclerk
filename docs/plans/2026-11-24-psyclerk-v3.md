# PsyClerk v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the single-file v2 clerking tool into an offline, phone-and-PC app with several patient drafts per device, saved phrases, a cleaner layout, and (if the BM-English test passes) on-device voice transcription.

**Architecture:** Static files only, no server and no build step at runtime. One `index.html` plus classic `<script>` files (not ES modules, so it still works opened straight from disk via `file://`). All patient data lives in the browser's `localStorage` on that device. A service worker caches everything for offline use when hosted.

**Tech Stack:** HTML, vanilla JS, Tailwind CSS v3 (compiled once with the CLI, replacing the CDN), Font Awesome 6 (local files), Playwright library + `node:test` for tests.

**Spec:** `docs/specs/2026-11-24-psyclerk-v3-design.md`

## Global Constraints
- No patient data leaves the device: no `fetch`/XHR/beacon with form content, ever. The only allowed network use is loading the app's own files and (Phase 2) the speech model download.
- No ES modules and no runtime CDN: `index.html` must work from `file://` with the network fully blocked.
- Every v2 safety behaviour stays and stays tested: `[NOT ASSESSED]`/`[NOT RECORDED]` for blanks, required risk ratings and basis for judgement, the copy/print block, consistency checks, matrix rows 1 and 3 mirroring C and L, Clear resetting everything.
- Draft auto-delete: **24 h after last edit on "My own phone or laptop", 12 h on "Shared ward PC"**. Device type is asked at first open and can be changed in settings.
- Expiry warning shown when a draft has **< 60 min** left ("deletes in 45 min").
- **Max 10 drafts per device.**
- Draft list shows a **short label you set** (placeholder `Bed 12 · AB`), never the patient name field.
- **End session** deletes all drafts on the device. **Done** deletes one draft. Phrases are never deleted by either.
- Phone layout applies below **1024 px**; tap targets at least **40 px** tall there.

## Review Focus
1. **Switching patient while an autosave is pending:** the pending save must not write patient A's form into patient B's draft (cross-patient contamination). Test in Task 3.
2. **An expired draft still on screen** (PC left open overnight): purge must also clear the form, and the next autosave must not bring the deleted data back. Test in Task 3.
3. **Storage unavailable or full** (Safari private mode, quota): show a visible "Drafts can't be saved on this device" warning instead of failing silently. Test in Task 2.
4. **Two tabs open on one device:** saving draft 1 in tab A must not erase draft 2 saved in tab B. Each draft gets its own storage key. Test in Task 2.
5. **Drafts saved by an older version of the form:** restoring must refuse rather than tick the wrong chips. A form fingerprint is stored with each draft. Test in Task 2.

### Task 2: Draft storage core

**Files:**
- Create: `js/drafts-store.js`, `js/form-state.js`
- Test: `tests/drafts-store.test.js`

**Interfaces:**
- Produces (globals on `window.PsyDrafts`):
  - `ttlMs(deviceType: 'own'|'shared') -> number` (own `86400000`, shared `43200000`)
  - `getDeviceType() -> 'own'|'shared'|null`, `setDeviceType(t)`
  - `listDrafts(now: number) -> Draft[]`, newest first. `Draft = { id, label, mode, status: 'risk incomplete'|'ready', updatedAt, expiresAt, fingerprint, state }`
  - `createDraft(label: string, now) -> Draft | null` (null when 10 exist)
  - `saveDraft(id, state, meta: {mode, status}, now) -> boolean` (false if storage throws)
  - `loadDraft(id) -> Draft|null`; `deleteDraft(id)`; `deleteAllDrafts()`
  - `purgeExpired(now) -> string[]` (ids removed)
  - `storageAvailable() -> boolean`
  - Storage keys: `psyclerk.device`, `psyclerk.draft.<id>` (one key per draft), `psyclerk.active`
- Produces (`window.PsyForm`):
  - `captureForm() -> { mode, format, fields: {id: value}, chips: number[], chipTexts: string[] }`. Chips are indexed by document order of `[onclick^="toggleChip"],[onclick^="selectSingleChip"]`.
  - `restoreForm(state) -> boolean`. Returns false and changes nothing if `formFingerprint()` differs from the saved one.
  - `formFingerprint() -> string` (chip count + hash of all chip texts + field ids)
  - `clearFormSilently()` (the v2 Clear body, without the modal)

- [ ] **Step 1: Failing tests:**
  - `ttl`: `ttlMs('own')===86400000`, `ttlMs('shared')===43200000`.
  - `cap`: creating 11 drafts → 11th returns `null`, `listDrafts().length===10`.
  - `purge`: draft on shared device updated at `t`, `purgeExpired(t+43200001)` removes it; own device, same times → kept; `t+86400001` → removed.
  - `roundtrip`: tick "Plan" + "Intent", type HPI, set `comp_suicide_level='High'`, `captureForm` → `clearFormSilently` → `restoreForm` → note text equal to before.
  - `fingerprint mismatch`: tamper `fingerprint` → `restoreForm` returns false and form stays blank.
  - `two tabs` (Review Focus 4): page A saves draft 1, page B (same context) saves draft 2 → both in `listDrafts`.
  - `storage throws` (Review Focus 3): stub `localStorage.setItem` to throw → `saveDraft` returns false, `storageAvailable()` false.
- [ ] **Step 2:** Run `node --test tests/drafts-store.test.js`. Expected: FAIL (`PsyDrafts is not defined`).
- [ ] **Step 3:** Implement both files per the interfaces. `expiresAt = updatedAt + ttlMs(device)`, recomputed on read so changing the device type applies at once. Ids from `crypto.randomUUID()`.
- [ ] **Step 4:** Run tests. Expected: PASS, plus the full `npm test`.

### Task V1: In-app transcription (after "go")
**Files:** Create `js/voice.js`, `js/voice-worker.js`, `vendor/transformers/`; Test `tests/voice.test.js`.
**Interfaces:** `startRecording(targetEl, kind: 'patient'|'self')`, `stopAndTranscribe() -> Promise<string>`.
**Behaviour:** Mic button on HPI, interval notes and MSE notes. `kind='patient'` requires ticking "Verbal consent for audio recording obtained" first and adds that line to the note. Audio is held in memory only and released after transcription. Transcription runs in a Web Worker (WebGPU if available, else WASM). Output is inserted under `[Transcribed: verify before filing]`. The model is downloaded on first use with a progress bar and a size warning (~250 MB for whisper-small, measured in V0).
**Tests:** consent gate blocks `patient` recording until ticked; consent line appears in the note; a fixture WAV produces non-empty text inserted with the marker; network log during transcription shows only model-file requests and no request body containing audio.
